# QSGA V7Plus 详细实现路径文档

## 1. 项目定位

### 1.1 项目名称

**QSGA: A Reliable Quantitative Strategy Generation Agent for Novice Users via Constrained Intermediate Representation and Verification-Guided Repair**

中文可理解为：

**QSGA：面向量化新手的可信量化策略生成 Agent 框架**

------

## 1.2 核心目标

本项目旨在构建一个面向非专业量化用户的可信策略生成系统。系统不让大语言模型直接生成 Python 策略代码，而是先将自然语言投资意图转换为一个受约束的策略中间表示 QYIR，然后通过多阶段验证链对策略进行语义一致性、结构合法性、执行可用性和风险可控性检查，并在失败时进行自动修复。

最终目标不是做一个完整商业级量化平台，而是实现一个**论文验证型原型系统**，用于支撑 CCF C 级别论文的实验与论证。

------

## 1.3 一句话科研定位

> QSGA is a reliable quantitative strategy generation agent that converts novice users' natural language investment intents into a constrained intermediate representation and improves strategy reliability through semantic verification, compilation verification, risk auditing, and verification-guided repair.

------

## 1.4 系统核心链路

```text
Natural Language Investment Intent
        ↓
LLM-based QYIR Generation
        ↓
Semantic Verification
        ↓
Schema Verification
        ↓
Compilation Verification
        ↓
Backtest Execution
        ↓
Risk Auditing
        ↓
Verification-Guided Repair
        ↓
Executable Strategy + Explanation + Risk Report
```

```text

        ↓
大模型生成 QYIR

        ↓

        ↓

最终策略、回测结果、风险解释
```

# 2. 项目总体实现原则

## 2.1 不做什么

为了控制工作量，V7Plus 不做以下内容：

1. 不做完整证券交易系统。
2. 不做真实下单。
3. 不做多市场多资产复杂适配。
4. 不做复杂前端。
5. 不做高频交易。
6. 不做强化学习策略优化。
7. 不做复杂因子挖掘。
8. 不做大型金融知识图谱。
9. 不做完整自然语言语义理解系统。
10. 不承诺策略收益。

这不是偷懒，是科研工程的“减脂增肌”。我们保留论文最有价值的骨架，把容易拖死人的肉砍掉。🦴

------

## 2.2 必须做什么

V7Plus 必须完成以下核心能力：

1. 定义 QYIR 策略中间表示。
2. 实现自然语言到 QYIR 的生成。
3. 实现 QYIR Schema 验证。
4. 实现显式语义槽位验证。
5. 实现 QYIR 到可执行回测逻辑的转换。
6. 实现轻量回测器。
7. 实现风险审计模块。
8. 实现自动修复模块。
9. 实现 Safe Rejection。
10. 构建 QSI-Bench 小型测试集。
11. 实现实验脚本。
12. 输出对比实验和消融实验结果。

# 4. 第一阶段：定义 QYIR

## 4.1 阶段目标

先定义一个受约束的量化策略中间表示 QYIR。

QYIR 是整篇论文的核心地基。它的作用是：

1. 避免 LLM 直接生成不可控 Python 代码。
2. 将模糊自然语言变成结构化策略语义。
3. 便于验证器检查。
4. 便于编译器转换成可执行策略。
5. 便于风险审计和自动修复。

------

## 4.4 Pydantic Schema 设计

文件：

```text
qyir/schema.py
```

建议定义：

```python
from typing import List, Dict, Optional, Any
from pydantic import BaseModel, Field


class MarketConfig(BaseModel):
    symbol: str
    timeframe: str = "1d"
    start_date: str
    end_date: str


class IndicatorConfig(BaseModel):
    name: str
    params: Dict[str, Any]
    alias: str


class RuleConfig(BaseModel):
    type: str
    left: str
    right: Any


class RiskControlConfig(BaseModel):
    position_size: float = Field(ge=0, le=1)
    stop_loss: Optional[float] = None
    take_profit: Optional[float] = None
    max_drawdown_limit: Optional[float] = None
    allow_short: bool = False
    leverage: float = Field(default=1.0, ge=1.0)


class QYIR(BaseModel):
    strategy_name: str
    description: Optional[str] = None
    market: MarketConfig
    indicators: List[IndicatorConfig]
    entry_rules: List[RuleConfig]
    exit_rules: List[RuleConfig]
    risk_control: RiskControlConfig
```

```python
import pandas as pd


def sma(series: pd.Series, window: int) -> pd.Series:
    return series.rolling(window=window).mean()


def ema(series: pd.Series, window: int) -> pd.Series:
    return series.ewm(span=window, adjust=False).mean()


def rsi(series: pd.Series, window: int = 14) -> pd.Series:
    delta = series.diff()
    gain = delta.clip(lower=0).rolling(window).mean()
    loss = -delta.clip(upper=0).rolling(window).mean()
    rs = gain / loss
    return 100 - 100 / (1 + rs)


def macd(series: pd.Series, fast: int = 12, slow: int = 26, signal: int = 9):
    ema_fast = ema(series, fast)
    ema_slow = ema(series, slow)
    macd_line = ema_fast - ema_slow
    signal_line = ema(macd_line, signal)
    return macd_line, signal_line


def bollinger(series: pd.Series, window: int = 20, num_std: float = 2.0):
    mid = sma(series, window)
    std = series.rolling(window).std()
    upper = mid + num_std * std
    lower = mid - num_std * std
    return upper, mid, lower
```

```python
def cross_over(left, right):
    return (left.shift(1) <= right.shift(1)) & (left > right)


def cross_under(left, right):
    return (left.shift(1) >= right.shift(1)) & (left < right)


def greater_than(left, right):
    return left > right


def less_than(left, right):
    return left < right


def between(value, lower, upper):
    return (value >= lower) & (value <= upper)
```

```python
import numpy as np


def total_return(equity_curve):
    return equity_curve.iloc[-1] / equity_curve.iloc[0] - 1


def annualized_return(equity_curve, periods_per_year=252):
    total_ret = total_return(equity_curve)
    n_periods = len(equity_curve)
    return (1 + total_ret) ** (periods_per_year / n_periods) - 1


def sharpe_ratio(strategy_returns, periods_per_year=252):
    if strategy_returns.std() == 0:
        return 0
    return np.sqrt(periods_per_year) * strategy_returns.mean() / strategy_returns.std()


def max_drawdown(equity_curve):
    running_max = equity_curve.cummax()
    drawdown = equity_curve / running_max - 1
    return drawdown.min()
```

## 8.3 验证规则示例

文件：

```text

```

示例逻辑：

```python
def semantic_verify(user_query: str, qyir: dict):
    violations = []
    risk = qyir.get("risk_control", {})

    if "不要杠杆" in user_query and risk.get("leverage", 1.0) > 1.0:
        violations.append({
            "type": "semantic_violation",
            "message": "User explicitly forbids leverage, but QYIR uses leverage."
        })

    if "不要做空" in user_query and risk.get("allow_short", False):
        violations.append({
            "type": "semantic_violation",
            "message": "User explicitly forbids short selling, but QYIR allows short selling."
        })

    if ("稳" in user_query or "低风险" in user_query) and risk.get("position_size", 1.0) > 0.5:
        violations.append({
            "type": "semantic_violation",
            "message": "Conservative intent conflicts with high position size."
        })

    if "不要满仓" in user_query and risk.get("position_size", 1.0) >= 0.9:
        violations.append({
            "type": "semantic_violation",
            "message": "User forbids full-position trading, but QYIR uses near full position."
        })

    return violations
```

# 9. 第六阶段：实现风险审计

## 9.1 阶段目标

风险审计是 QSGA 区别于普通代码生成系统的重要模块。

它负责判断策略是否存在明显风险问题。

------

## 9.2 风险审计规则

第一版支持：

```text
1. position_size > 1.0，直接拒绝。
2. leverage > 1.0，高风险警告。
3. stop_loss 缺失，风险警告。
4. max_drawdown 超过阈值，风险警告。
5. num_trades 过少，样本不足警告。
6. sharpe_ratio 过低，策略质量警告。
7. total_return 很高但 max_drawdown 极大，风险收益不平衡警告。
```

------

## 9.3 风险等级

建议分为：

```text

```

# 10. 第七阶段：实现 Safe Rejection

## 10.1 阶段目标

对于危险、非法、不现实、不可结构化的请求，系统应该拒绝，而不是硬生成策略。

Safe Rejection 是金融场景中很有价值的模块，工作量不大，但论文收益很高。

------

## 10.2 需要拒绝的请求类型

```text
1. 保证收益类
2. 稳赚不赔类
3. 一夜暴富类
4. 高杠杆梭哈类
5. 内幕交易类
6. 规避监管类
7. 操纵市场类
8. 过于模糊无法结构化类
9. 系统不支持的资产或策略类型
```

------

## 10.3 示例

用户输入：

```text
帮我生成一个稳赚不赔、一个月翻倍的策略
```

输出：

```json
{
  "status": "rejected",
  "reason": "The request contains unrealistic guaranteed-return expectations and violates risk safety constraints."
}
```

------

## 10.4 简单实现方式

文件：

```text
verifier/safe_rejection.py
```

关键词规则即可：

```python
UNSAFE_PATTERNS = [
    "稳赚",
    "稳赚不赔",
    "保证收益",
    "一定赚钱",
    "一个月翻倍",
    "内幕消息",
    "规避监管",
    "操纵市场",
    "满仓梭哈",
    "十倍杠杆"
]


def should_reject(user_query: str):
    for pattern in UNSAFE_PATTERNS:
        if pattern in user_query:
            return True, f"Unsafe request detected: {pattern}"
    return False, None
```

------

## 10.5 阶段验收标准

第七阶段完成后，应该满足：

```text
1. 能拒绝保证收益类请求。
2. 能拒绝内幕交易类请求。
3. 能拒绝高风险梭哈类请求。
4. 能统计 Safe Rejection Accuracy。
```

# 11. 第八阶段：实现自动修复

## 11.1 阶段目标

当 QYIR 没有通过验证时，系统将验证错误反馈给 LLM，要求其修复 QYIR。

------

## 11.2 修复流程

```text
Generate QYIR
        ↓
Verify QYIR
        ↓
If failed, collect violations
        ↓
Construct repair prompt
        ↓
LLM repairs QYIR
        ↓
Verify again
        ↓
Max repair rounds = 2
```

------

## 11.3 修复 Prompt 示例

文件：

```text
repair/repair_prompt.py
The generated QYIR failed verification.

Original user query:
{user_query}

Current QYIR:
{qyir}

Violations:
{violations}

Please repair the QYIR while preserving the user's original intent.

Requirements:
1. Output valid JSON only.
2. Do not output Python code.
3. Fix all listed violations.
4. Keep the strategy within supported QYIR schema.
```

------

## 11.4 修复策略

第一版支持两种修复方式：

```text
1. Rule-based Repair
2. LLM-based Repair
```

建议先实现 LLM-based Repair，再补几个简单 Rule-based Repair。

例如：

```text
如果用户说不要杠杆，但 leverage > 1，则直接设置 leverage = 1.0。
如果用户说稳一点，但 position_size > 0.5，则设置 position_size = 0.3。
如果用户说不要做空，则设置 allow_short = false。
```

------

## 11.5 阶段验收标准

第八阶段完成后，应该满足：

```text
1. 验证失败后可以触发修复。
2. 修复后重新验证。
3. 最多修复 2 轮。
4. 记录 repair trace。
```

repair trace 示例：

```json
{
  "round": 1,
  "violations_before": [
    "User forbids leverage, but QYIR uses leverage = 2."
  ],
  "repair_action": "Set leverage to 1.0.",
  "passed_after_repair": true
}
```

# 15. 第十二阶段：实验指标设计

## 15.1 主指标

| 指标                     | 含义                       |
| ------------------------ | -------------------------- |
| Schema Validity Rate     | QYIR 是否符合结构约束      |
| Semantic Consistency     | 是否符合用户显式意图       |
| Compilation Success Rate | 是否能转换为可执行策略     |
| Backtest Success Rate    | 是否能完成回测             |
| Risk Violation Rate      | 是否存在风险违规，越低越好 |
| Repair Success Rate      | 修复后通过验证的比例       |
| Safe Rejection Accuracy  | 对危险请求的拒绝准确率     |
| End-to-End Success Rate  | 完整链路成功率             |

------

## 15.2 指标计算方式

### Schema Validity Rate

```text
合法 QYIR 数量 / 总生成数量
```

### Semantic Consistency

```text
符合 expected_slots 的样本数量 / 非拒绝样本数量
```

### Compilation Success Rate

```text
成功生成 signals 的样本数量 / 非拒绝样本数量
```

### Backtest Success Rate

```text
成功完成回测的样本数量 / 非拒绝样本数量
```

### Risk Violation Rate

```text
存在风险违规的样本数量 / 非拒绝样本数量
```

### Repair Success Rate

```text
修复后通过验证的样本数量 / 触发修复的样本数量
```

### Safe Rejection Accuracy

```text
正确拒绝 unsafe request 的数量 / unsafe request 总数
```

### End-to-End Success Rate

```text
完整通过生成、验证、编译、回测、风险审计的样本数量 / 总样本数量
```

# 24. 关键风险与应对方案

## 24.1 风险一：LLM 输出 JSON 不稳定

解决：

```text
1. 强制 JSON-only prompt。
2. 使用 schema validator。
3. 解析失败则触发 repair。
4. 最多重试 2 次。
```

------

## 24.2 风险二：Semantic Verification 被质疑主观

解决：

```text
1. 明确只验证显式槽位。
2. 不声称理解所有模糊意图。
3. 在论文中写清楚能力边界。
4. benchmark 标注时只标注显式语义。
```

------

## 24.3 风险三：回测器太简单

解决：

```text
1. 论文中说明这是 execution verification，不是生产级交易引擎。
2. 强调目标是验证策略可执行性。
3. 支持基础指标即可。
4. 不将收益表现作为核心贡献。
```

------

## 24.4 风险四：工作量膨胀

解决：


# 26. 总结

QSGA V7Plus 的实现路线应该遵循：

```text
先结构化，再可执行；
先验证，再修复；
先闭环，再扩展；
先实验，再美化。
```

最终你要做出的不是一个“万能量化 Agent”，而是一个**可验证、可对比、可实验、可写论文的可信策略生成原型系统**。

它的核心价值不是策略收益有多高，而是证明：

> 相比直接让 LLM 生成代码，基于 QYIR 的受约束生成和多阶段验证修复机制，可以显著提升量化策略生成在结构合法性、语义一致性、执行成功率和风险可控性上的可靠性。

这就是你的 CCF C 主线。
一句话：**别让大模型裸奔写策略，让它穿上 QYIR 这件学术防弹衣。** 🦺📈
