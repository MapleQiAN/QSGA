# AI 科研全流程标准作业程序

## 1. 适用范围

本 SOP 规范 AI 如何执行科研工作流。它适用于论文构思、文献综述、实验设计、实验执行、结果分析、论文写作、审稿模拟和归档复现。

本 SOP 不规定系统开发实现细节，不要求 AI 构建软件平台。若需要开发工具，应另开工程任务，并不得影响科研流程记录的完整性。

## 2. 总体阶段

| 阶段 | 自动化级别 | 必须人审 | 首选 skill/plugin |
|---|---|---:|---|
| S0 任务接收与范围界定 | 半自动 | 是 | `bmad-domain-research` |
| S1 领域地图与问题空间 | 自动 | 否 | `bmad-domain-research`, `Hugging Face` |
| S2 文献发现与筛选 | 自动 | 可选 | `Hugging Face`, web search |
| S3 文献精读与证据抽取 | 自动 | 抽样审核 | `bmad-technical-research` |
| S4 研究空白与假设生成 | 半自动 | 是 | `bmad-domain-research`, reviewer Agent |
| S5 实验方案设计 | 半自动 | 是 | `bmad-technical-research` |
| S6 实验执行与记录 | 自动 | 异常时 | `automation-workflows`, GitHub/Codex |
| S7 结果分析与解释 | 半自动 | 是 | `bmad-technical-research` |
| S8 论文写作 | 半自动 | 是 | `documents`, Markdown 编辑 |
| S9 审稿模拟与修订 | 半自动 | 是 | `bmad-advanced-elicitation` |
| S10 发布、归档、复现包 | 半自动 | 是 | `automation-workflows`, GitHub |

## 3. S0 任务接收与范围界定

### 目标

把模糊科研意图变成可执行的研究任务说明。

### AI 自动执行

1. 提取研究主题、目标领域、预期产出、时间约束、资源约束。
2. 判断任务属于实证研究、方法研究、综述研究、复现实验、工程系统论文或理论分析。
3. 创建运行记录，登记任务 ID、时间、输入、已知限制。
4. 初始化 `DECISIONS.md`，记录需要人类确认的问题。

### 必须人审

1. 最终研究目标。
2. 是否允许使用特定数据集、平台、模型或商业 API。
3. 是否涉及伦理、隐私、安全、金融、医疗、法律等高风险领域。

### 阻塞处理

如果研究目标未确认，AI 不得进入结论性写作，但可以继续做以下非阻塞任务：

1. 建立领域术语表。
2. 搜集候选论文。
3. 整理相邻研究方向。
4. 生成初步问题树。

## 4. S1 领域地图与问题空间

### 目标

建立领域背景、关键术语、主流任务、评价指标和未解决问题。

### AI 自动执行

1. 调用 `bmad-domain-research` 建立领域结构。
2. 用 `Hugging Face`、学术搜索和会议页面搜集代表性论文。
3. 生成领域地图：任务、方法、数据集、指标、应用场景、主要争议。
4. 标记不确定事实，并要求后续证据补强。

### 产出

1. `domain-map.md`
2. `terminology.md`
3. `open-problems.md`

### 质量要求

每个关键判断必须至少有一个可信来源。没有来源的判断只能标记为“推测”。

## 5. S2 文献发现与筛选

### 目标

系统化发现相关论文，并建立可追踪的筛选记录。

### AI 自动执行

1. 并行检索：关键词检索、引文追踪、作者追踪、会议追踪、数据集追踪。
2. 对每篇论文记录标题、作者、年份、venue、URL、DOI/arXiv、代码、数据集。
3. 初筛论文相关性，分为核心、相关、背景、排除四类。
4. 对排除论文写明排除原因。

### 首选插件

1. `Hugging Face`：AI/ML 论文、模型、数据集检索。
2. web search：官方页面、arXiv、会议、期刊、数据集。
3. Browser 工具：核验网页内容、下载 PDF、检查代码仓库。

### 必须人审

若 AI 准备排除高引用、高相关或人类指定论文，必须登记决策项，不得直接删除。

## 6. S3 文献精读与证据抽取

### 目标

把论文内容转为结构化证据，而不是只生成摘要。

### AI 自动执行

每篇核心论文必须建立论文卡片：

1. 研究问题。
2. 方法核心。
3. 实验设置。
4. 数据集。
5. 指标。
6. Baseline。
7. 主要结果。
8. 局限。
9. 可复现材料。
10. 可被本研究复用或挑战的点。

### 证据格式

```text
Claim:
Source:
Evidence location:
Confidence:
Used for:
Risk:
```

### 必须人审

1. 任何将被写入 Introduction 或 Related Work 的关键比较。
2. 任何对他人工作的负面评价。
3. 任何“首次”“显著优于”“SOTA”等强主张。

## 7. S4 研究空白与假设生成

### 目标

从证据中生成可检验的研究假设，而不是凭空发散。

### AI 自动执行

1. 基于文献矩阵找出未解决问题。
2. 生成候选假设。
3. 给每个假设标注证据来源、创新性、可验证性、实验成本、失败风险。
4. 组织 reviewer Agent 进行反驳。

### 必须人审

人类必须选择或修改最终研究问题。AI 不得自行冻结研究问题。

### 决策写入规则

若存在多个可行假设，AI 必须写入 `DECISIONS.md`：

```text
Decision ID:
Question:
Options:
AI recommendation:
Evidence:
Risk if wrong:
Non-blocked work AI will continue:
```

## 8. S5 实验方案设计

### 目标

定义实验协议，使结果可复现、可解释、可被审稿人检查。

### AI 自动执行

1. 设计主实验、baseline、消融、敏感性分析、失败案例分析。
2. 定义数据集版本、样本规模、指标、统计检验方法。
3. 估算计算成本和时间成本。
4. 写明预期结果和可能推翻假设的结果。

### 必须人审

1. 实验协议冻结。
2. Baseline 选择。
3. 数据集合法性。
4. 指标是否足以支撑论文主张。

### 禁止

1. 看过结果后再偷偷改主指标。
2. 删除失败实验但不登记。
3. 只报告支持假设的结果。

## 9. S6 实验执行与记录

### 目标

自动运行实验并保留完整审计轨迹。

### AI 自动执行

1. 运行已批准实验。
2. 记录环境、依赖、随机种子、数据版本、命令、开始/结束时间。
3. 保存 stdout、stderr、异常、日志和结果文件。
4. 自动生成实验状态表。

### 异常处理

如果实验失败：

1. AI 可自动排查环境、路径、依赖、格式错误。
2. 如果失败会改变实验设计，必须写入 `DECISIONS.md`。
3. AI 应继续运行不依赖失败分支的实验。

## 10. S7 结果分析与解释

### 目标

将实验结果转化为谨慎、可证据追溯的科研结论。

### AI 自动执行

1. 汇总主结果、消融、失败案例。
2. 检查结果是否支持原假设。
3. 生成图表和表格。
4. 识别异常值和潜在数据泄漏。
5. 生成“支持结论”和“反对结论”的双列表。

### 必须人审

1. 最终结论。
2. 结果解释。
3. 是否需要补实验。
4. 是否可以进入论文写作。

## 11. S8 论文写作

### 目标

生成可审阅论文草稿，但不替代人类最终判断。

### AI 自动执行

1. 生成大纲。
2. 写作 Introduction、Related Work、Method、Experiments、Limitations。
3. 将每个事实性主张绑定证据。
4. 维护 citation map。

### 必须人审

1. 标题、摘要、贡献点。
2. 署名、致谢、利益冲突。
3. Limitations 是否充分。
4. 投稿版本。

## 12. S9 审稿模拟与修订

### 目标

用多个 reviewer Agent 模拟审稿，提前发现拒稿风险。

### AI 自动执行

至少启动以下 reviewer 角色：

1. Novelty Reviewer：检查创新性不足。
2. Soundness Reviewer：检查实验和结论是否匹配。
3. Reproducibility Reviewer：检查复现材料。
4. Clarity Reviewer：检查结构和表达。
5. Ethics Reviewer：检查伦理和风险声明。

### 必须人审

人类决定哪些审稿意见必须采纳。AI 可以提出建议，但不得擅自删除研究主张。

## 13. S10 发布、归档、复现包

### 目标

形成可长期追踪的科研资产。

### AI 自动执行

1. 生成 artifact manifest。
2. 检查论文、代码、数据、图表、日志是否一致。
3. 生成复现说明。
4. 整理最终 citation list。

### 必须人审

1. 投稿。
2. 公开仓库。
3. 数据发布。
4. 许可协议。
5. 署名和贡献声明。
