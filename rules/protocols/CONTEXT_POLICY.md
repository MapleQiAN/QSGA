# Context Policy

本文件定义 Research Ops 的上下文读取、压缩和预算策略。目标是避免“为了省上下文创建大量文档，结果每轮又把所有文档读一遍”的反向炼丹炉问题。

---

## TLDR_STATE_FOR_AGENT

默认读取：

- `AGENTS.md` 摘要区
- `TASK_QUEUE.md` Top Active Tasks
- `CURRENT_PROGRESS.md` 摘要区和 Next Actions
- `DECISIONS.md` PendingReview / waiting_human
- `RISKS.md` Critical / High active
- `protocols/EXECUTION_LOOP.md`

禁止默认读取：

- 全量实验日志
- 全量论文草稿
- 全量文献矩阵
- 全量历史 runs
- 全量源代码仓库
- 全量附件和数据集

长文档必须优先读：

```markdown
## TLDR_STATE_FOR_AGENT
当前有效结论：
当前阻塞：
最近更新：
下一步：
```

---

## 1. 默认读取预算

每轮启动时，Agent 的默认上下文预算应控制在以下范围：

| 内容 | 默认读取量 |
|---|---|
| 主规范 | 只读摘要区和必要规则 |
| 任务队列 | 读 Active Tasks 中 Top 5 到 Top 10 |
| 当前进度 | 读摘要区、当前阶段、Next Actions |
| 决策队列 | 只读 PendingReview / waiting_human |
| 风险队列 | 只读 Critical / High active |
| 历史运行记录 | 默认不读，只在追溯时读取最近 1 到 3 条 |
| 文献矩阵 | 默认不读全量，只读相关 claim 或 paper |
| 实验结果 | 默认不读全量，只读相关实验 ID |
| 论文草稿 | 默认不读全量，只读当前任务涉及章节 |

---

## 2. 何时允许扩大读取范围

只有以下情况可以扩大读取范围：

1. 当前任务明确要求精读某个文档。
2. 任务依赖无法从摘要区判断。
3. 出现冲突，需要追溯证据。
4. 需要核验引用、实验结果或 claim。
5. 人类明确要求“全面检查”“完整审稿”“通读全文”。
6. 工具或文件状态异常，需要排错。

扩大读取后必须在运行记录中说明：

```text
Expanded Context:
Reason:
Files Read:
Sections Read:
Result:
```

---

## 3. 禁止行为

禁止：

1. 每轮都说“我需要完整上下文”，然后读取全部文档。
2. 每轮都读取全部历史 runs。
3. 每轮都读取全部论文草稿。
4. 为了补一点格式读取全部文献矩阵。
5. 把源代码仓库当作默认上下文。
6. 复制长文档到运行记录。
7. 让摘要区过度膨胀，变成第二份全文。

---

## 4. TLDR_STATE_FOR_AGENT 标准格式

所有长期维护文档建议在顶部使用：

```markdown
## TLDR_STATE_FOR_AGENT

当前有效结论：
- 

当前阻塞：
- 

最近更新：
- 

下一步：
- 

需要注意：
- 
```

如果是任务类文档，使用：

```markdown
## TLDR_STATE_FOR_AGENT

当前最高优先级任务：
- 

当前阻塞任务：
- 

可自动执行任务：
- 

需要人类确认：
- 

下一步推荐：
- 
```

如果是实验类文档，使用：

```markdown
## TLDR_STATE_FOR_AGENT

当前实验协议状态：
- draft / frozen / revision_needed

已完成实验：
- 

关键结果：
- 

失败结果：
- 

未验证 claim：
- 

下一步：
- 
```

## 5. 摘要更新原则

更新摘要区时：

1. 只写当前仍然有效的信息。
2. 过期信息移到正文历史区。
3. 明确区分“已验证”和“未验证”。
4. 每条尽量短。
5. 引用实验 ID、任务 ID、决策 ID，而不是复制全文。
6. 不写情绪化描述。
7. 不写“详见上文”这种对下一轮无帮助的话。

---

## 6. 上下文压缩策略

每轮结束时，Agent 应将过程压缩成三类信息：

### 6.1 Carry Forward

下一轮必须知道的信息：

```text
Context to Carry Forward:
- 当前阶段：
- 当前任务：
- 新证据：
- 新风险：
- 下一步任务：
```

### 6.2 Archive

可以归档，不必每轮读取的信息：

```text
Archive:
- 详细工具日志
- 完整实验输出
- 中间推理草稿
- 旧版本草稿
```

### 6.3 Human Review

需要人类处理的信息：

```text
Human Review:
- 决策项：
- 推荐选项：
- 风险：
- 默认假设：
```

## 7. 文件读取优先级

当多个文件都可能相关时，优先级如下：

1. `TASK_QUEUE.md`
2. `CURRENT_PROGRESS.md`
3. `DECISIONS.md`
4. `RISKS.md`
5. 当前任务直接输入文件
6. 当前任务证据文件
7. 历史 runs
8. 全量草稿或全量矩阵

原则：先读状态，再读任务，再读证据，最后才读历史。

---

## 8. 长文档分块策略

处理长文档时，必须：

1. 先读目录和摘要区。
2. 定位当前任务相关章节。
3. 只读取相关章节。
4. 产出局部结论。
5. 如果局部结论不足，再扩大范围。
6. 记录扩大范围的原因。

---

## 9. 对代码仓库的上下文策略

除非任务要求，否则不要全仓库扫描。

默认代码读取策略：

1. 先读 README、目录结构、测试入口。
2. 再读当前任务相关文件。
3. 再读相关测试。
4. 最后才读调用链上游和下游。
5. 修改前必须确认文件职责。
6. 修改后必须运行或说明无法运行的验证方式。

---

## 10. 对论文写作的上下文策略

论文写作时，禁止直接凭记忆写强结论。

必须读取：

1. 当前章节草稿。
2. 相关 claim 的证据等级。
3. 相关实验结果或文献证据。
4. 相关 reviewer 风险。

不必默认读取：

1. 全文所有章节。
2. 所有文献卡片。
3. 所有历史审稿意见。
