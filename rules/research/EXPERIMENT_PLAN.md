## Research Questions

1. RQ1: Can constrained natural-language-to-QYIR construction improve structural validity, semantic consistency, and executable construction success of LLM-generated strategy specifications?
2. RQ2: Which components reduce which failure modes: structured slot extraction, deterministic QYIR building, canonicalization, validation-feedback retry, safe rejection, and QSGA backend repair?
3. RQ3: Under the same QSI-Bench constraints, does Full QSGA-B outperform raw QYIR prompting and direct-code/direct-JSON baselines without weakening risk constraints?

## Route B Safety and Cost Rules

1. Do not overwrite raw outputs; every live run writes a new timestamped or method-specific JSONL/CSV/metadata set under `experiments/results/`.
2. Do not write improved construction-success numbers into the manuscript until generated by a recorded experiment entry in `RESULTS_LOG.md`.
3. Small smoke runs may use the user-provided `DSAPIKEY.txt` only after the command records model, case IDs or case limit, max tokens, output paths, and budget expectation.
4. Batch or full live API runs require an explicit task status update and recorded sample/budget scope, even though the user has allowed DeepSeek model use in principle.
5. Prefer official DeepSeek `deepseek-v4-flash` at `https://api.deepseek.com` for low-cost smoke tests; reserve `deepseek-v4-pro` for targeted comparison after smoke results justify it.
6. If a method changes QYIR semantics, such as adding `market.close` operands, record a design decision before changing the frozen validator/compiler contract.
